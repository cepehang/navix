# AGENTS.md

Guidance for AI coding agents working in this repository.

## Overview

**Navix** is a single-host NixOS media server configured as a flake. The media stack
(Jellyfin, the *arr apps, qBittorrent behind a VPN, DDNS) is provided by
[Nixarr](https://github.com/nix-media-server/nixarr). User-level config is managed by
Home Manager, wired in as a NixOS module (there is no standalone Home Manager config).

- Host / flake output: `nixosConfigurations.navix` (`x86_64-linux`)
- Channel: `nixos-unstable`, `system.stateVersion = "26.05"`
- Primary user: `cepehang`

## Layout

| Path | Purpose |
| --- | --- |
| `flake.nix` | Inputs (nixpkgs, home-manager, agenix, nixarr, lazyvim) and the `navix` system |
| `nixos/configuration.nix` | Main system config: boot, NVIDIA, KDE Plasma, SSH, Nixarr services, users, agenix secrets |
| `nixos/hardware-configuration.nix` | Generated by `nixos-generate-config` (btrfs subvolumes). Avoid hand edits unless the hardware changes |
| `home-manager/home.nix` | Home Manager config for `cepehang` (zsh, git signing, neovim/LazyVim, CLI tools) |
| `secrets/agenix-rules.nix` | agenix recipients (laptop, pc, server SSH keys) |
| `secrets/*.age` | Encrypted secrets (`njalla-keys`, `wireguard`) |

## Common commands (nh)

The flake path is set through `programs.nh.flake`, so `nh` commands need no flake argument.

```sh
nh os build          # build the system without activating it (use this to check that changes evaluate/build)
nh os test           # build and activate, but don't add a boot entry
nh os switch         # build, activate, and make it the boot default
nh os boot           # build and make it the boot default on next reboot
nh os switch -u      # update flake inputs, then switch
nh clean all --keep 5  # garbage-collect old generations
nh search <query>    # search nixpkgs
```

Other useful commands:

```sh
nix fmt              # format all Nix files (nixfmt-tree)
nix flake check      # evaluate flake outputs
nix flake update [input]  # update the lockfile (or a single input)
```

## Working conventions

- **Flakes only see git-tracked files.** After creating a new file, `git add` it before
  building, or evaluation will fail with "path does not exist".
- **Verify with `nh os build`**, not `switch`. Activating the system (`switch`/`test`/`boot`)
  changes the running server; leave that to the user unless explicitly asked.
- Run `nix fmt` before committing.
- Prefer Nixarr options (`nixarr.<service>.*`) over configuring the underlying
  `services.<service>` directly. Upstream `services.*` settings are only used for things
  Nixarr doesn't expose (e.g. `settings.auth.required` on the *arr apps).
- Check option names against the Nixarr docs/source for the pinned revision; the input
  currently points to a fork (`github:cepehang/nixarr/add-12.2-hash`) rather than upstream.
- Media lives under `/data/media`; Nixarr state under `/data/media/.state/nixarr`.
- Commits are SSH-signed by default (configured in Home Manager). Use conventional-commit
  style messages (`feat:`, `fix:`, `chore:` …) to match history.

## Secrets (agenix)

- Never commit plaintext secrets or put secret values in Nix expressions; they would end
  up world-readable in the Nix store. Reference them through `config.age.secrets.<name>.path`.
- The rules file is `secrets/agenix-rules.nix` . The `agenix` CLI isn't installed
  system-wide; run it from the flake input:

  ```sh
  cd secrets
  nix run github:ryantm/agenix -- -e <name>.age   # create/edit
  nix run github:ryantm/agenix -- -r              # rekey after changing recipients
  ```

- To add a secret: add an entry to `agenix-rules.nix`, create the `.age` file, declare it in
  `age.secrets` in `configuration.nix`, and `git add` the new file.
- Editing secrets requires one of the recipients' private keys; agents typically can't
  decrypt them and should ask the user instead.
